## Solution

The solution uses a State struct to keep track of the dial. It stores the current position, how many instructions land exactly on zero, and how many times the dial clicks past zero.

The dial has 100 positions, so dialSize is set to 100. Every movement needs to wrap around this size.

```
type State struct {
	position     int
	landsOnZero  int
	clicksOnZero int
}

const dialSize = 100
```

Solve handles one instruction at a time. It reads the distance from the instruction, checks whether the movement is left or right, then updates the dial position.

After finding the new position, Solve returns an updated State. It adds to landsOnZero if the final position is zero, and it adds to clicksOnZero based on how many times the movement passed zero.

```

func Solve(state State, instruction string) (newState State) {
	distance, _ := strconv.Atoi(instruction[1:])

	movement := distance

	if instruction[0] == 'L' {
		movement = -distance
	}

	position := wrap(state.position + movement)

	return State{
		position:     position,
		landsOnZero:  state.landsOnZero + landsOnZero(position),
		clicksOnZero: state.clicksOnZero + clicksOnZero(distance, movement, state.position),
	}
}
```

The clicksOnZero function counts how many times a single instruction crosses zero. Full turns always pass zero once, and the remaining movement may pass zero one more time.

The landsOnZero function is small but keeps the zero-check separate. If the dial ends on position zero, it returns 1; otherwise, it returns 0.

```
func clicksOnZero(distance, movement, startPos int) int {
	fullTurns := distance / dialSize
	remainder := distance % dialSize

	if movement > 0 {
		if startPos+remainder >= dialSize {
			fullTurns++
		}
	} else {
		if startPos > 0 && startPos-remainder <= 0 {
			fullTurns++
		}
	}

	return fullTurns
}

func landsOnZero(position int) int {
	if position != 0 {
		return 0
	}
	return 1
}
```

The main function opens the input file and starts the dial at position 50. It then reads each instruction, updates the state, and prints the final totals.

```
func main() {

	file, err := os.Open("input.txt")
	if err != nil {
		log.Fatal(err)
	}
	defer file.Close()

	state := State{
		position: 50,
	}

	scanner := bufio.NewScanner(file)

	for scanner.Scan() {
		state = Solve(state, scanner.Text())
		fmt.Printf("State: %d\n", state)
	}

	if err := scanner.Err(); err != nil {
		log.Fatal("Scanning error")
	}

	fmt.Printf("Lands on 0 %d times\n", state.landsOnZero)
	fmt.Printf("Clicks on 0 %d times\n", state.clicksOnZero)

}
```

## Notes on Modulus on Negative Numbers

In Go, % doesn't mean modulo, it means remainder. Because of this, it cannot be used directly to find the modulus of negative numbers.

For example, -1 % 5 mathematically should be 4, but Go will evaluate it to be -1 because it truncates towards 0.

To solve this, first evaluate the expression and see whether the result is negative or positive (including the 0 case).

If it is positive, the answer is correct. If it is negative, add the divisor, which wraps the answer back into a positive value.

For example, -1 % 5 evaluates to -1, which is negative, so adding the divisor (-1 + 5) will give the correct answer of 4.

```
func modulo(a, b int) int {
    r := a % b
    if r < 0 {
        return r + b
    }
    return r
}
```

Simplifying further, adding b to the initial remainder allows the result to be wrapped back into bounds when the modulus is applied again. This eliminates the need for branching.

In other words,

- a % b: The initial remainder.

- (a % b) + b: Adding b ensures a negative result becomes positive, and a positive result gets pushed forward beyond the next boundary.

- ((a % b) + b) % b: The final modulo has no effect on the originally negative result, but safely wraps the positive result back into the correct boundary.

```
func wrap(a, b int) int {
	return ((a % b) + b) % b
}
```
